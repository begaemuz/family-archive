# Rodiva — семейный архив

> История вашей семьи принадлежит только вашей семье.

Родословное древо, фото, видео, аудио, документы и семейные истории — в **одном зашифрованном файле `.family`**.
Приложение работает целиком в браузере: ничего не отправляет на сервер, без аналитики, работает без интернета.

## Возможности

- **Древо:** карточки людей, связи (родители, дети, супруги, братья и сёстры, прочие), автовыравнивание по поколениям, сворачивание ветвей, линейка поколений, степени родства (двоюродные, троюродные, родня по браку).
- **Человек:** даты и места, контакты, ники в соцсетях (Telegram, WhatsApp, Instagram, ВКонтакте, Одноклассники, Facebook, X, TikTok, YouTube), биография разделами, место захоронения на карте.
- **Медиа:** фото, видео и аудио до 200 МБ на файл; документы (PDF, сканы, Word/Excel, текст).
- **Фото:** год снимка (выбор из сетки годов), отметки «Кто на фото».
- **Распознавание лиц:** при загрузке фото система узнаёт родных и спрашивает «Кажется, это Петя? Да / Нет». Узнаёт по фото профиля, по снимкам в альбоме человека, где одно лицо, и по вашим «Да» — они запоминаются в архиве. Всё считается на устройстве.
- **Семейные истории** с отмеченными людьми и файлами.
- **PDF-книга** для печати и отправки родственникам: обложка, оглавление, схема древа, страницы людей, истории, указатель имён.

## Безопасность

| | |
|---|---|
| Шифрование | AES-256-GCM (Web Crypto), файл режется на блоки по 4 МБ, у каждого блока свой случайный nonce |
| Ключ | Argon2id из пароля (64 МБ, 3 прохода), уникальная соль на каждый архив; ключ неизвлекаемый |
| Целостность | заголовок, номер и порядок блоков защищены (AAD) — подмена, перестановка и обрезка обнаруживаются |
| Пароль | нигде не хранится и никуда не передаётся; восстановить его нельзя |
| Черновик | несохранённые изменения лежат в IndexedDB **в зашифрованном виде** тем же ключом |
| Файлы | тип проверяется по содержимому (сигнатуре), HTML/SVG/скрипты не принимаются; содержимое архива никогда не выполняется |
| Сеть | приложение не обращается ни к одному внешнему адресу (закреплено в Content-Security-Policy). Карта Яндекса работает в отдельной изолированной рамке `map.html` (`sandbox` без `allow-same-origin`): ей передаются только координаты и текст поиска, к архиву у неё доступа нет |

Формат файла описан в [src/archive/container.ts](src/archive/container.ts) и [src/archive/format.ts](src/archive/format.ts).

## Запуск

Нужен [Node.js](https://nodejs.org) 18 или новее.

```bash
npm install
```

```bash
npm run dev
```

Откройте http://localhost:5173.

## Сборка

**Сайт** (например, для GitHub Pages) — в папку `dist/`. После первого открытия работает и без интернета.

```bash
npm run build
```

**Автономная версия** — один файл `dist-single/family-archive.html`. Его можно положить рядом с архивом на флешку или отправить родственникам: открывается двойным щелчком, интернет не нужен.

```bash
npm run build:single
```

## Тесты

```bash
npm test
```

Проверяются шифрование (неверный пароль, повреждение, обрезка, перестановка блоков, смена пароля), формат архива, даты, соцсети, степени родства и совпадение раскладки древа с прежней версией.

## Публикация на GitHub Pages

Публикация настроена в [.github/workflows/deploy.yml](.github/workflows/deploy.yml): при каждой отправке в ветку `main` GitHub сам прогоняет тесты, собирает приложение и выкладывает его.

Один раз нужно включить: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Пути в сборке относительные, поэтому сайт работает в подпапке `https://<логин>.github.io/<репозиторий>/`. На сайт попадает только приложение — семейные архивы `.family` остаются у вас.

## Карты

Карта места захоронения и поиск адреса — [JavaScript API Яндекс Карт](https://yandex.ru/dev/jsapi-v2-1/). Ключ лежит в `.env` (`VITE_YANDEX_MAPS_KEY`); он не секретный и в кабинете Яндекса ограничен адресами сайта (HTTP Referer). Без интернета карта не показывается, остальное работает.

## Распознавание лиц

[@vladmandic/face-api](https://github.com/vladmandic/face-api) (лицензия MIT) на TensorFlow.js. Фото **никуда не отправляются**: поиск и сравнение лиц идут в браузере.

Найденные лица сохраняются **внутри зашифрованного архива** (у фото — поле `faces`: рамка, «отпечаток» из 128 чисел, кто это и кого предложить), вместе с ответами «Да» и «Нет». Поэтому после перезапуска рамки и вопросы на месте, лица не ищутся заново, а каждое «Да» добавляет человеку ещё один образец — узнавание со временем становится точнее. Если узнали неверно — нажмите на рамку лица: «Это не …» снимает человека с этого лица (и больше его туда не ставит), а поиск позволяет указать, кто это на самом деле.

Модели (~7 МБ) лежат в пакете. При `npm install` / `dev` / `build` их копирует в `public/models` скрипт `scripts/copy-face-models.mjs`; в git они не хранятся. Модели загружаются при первом распознавании, после этого работают офлайн (кэш PWA `face-models`). В автономном однофайловом `family-archive.html` распознавание недоступно.

## Структура

```
src/
  domain/      данные и логика: типы, даты, родство, раскладка древа, линии
  archive/     формат .family: шифрование, контейнер, медиа, черновик
  store/       состояние (Zustand): архив, интерфейс, сессия
  flows/       сценарии: добавление людей, связи, файлы
  components/  интерфейс: шапка и стартовый экран, холст, панель человека, диалоги, истории
  pdf/         PDF-книга
  styles/      стили по разделам
legacy/        прежняя версия приложения (одним файлом) — для сверки
tests/         тесты Vitest
```
